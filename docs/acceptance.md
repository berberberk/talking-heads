# Acceptance-прогон перед демонстрацией

Этот чек-лист не использует synthetic оценки и не подменяет реальный provider smoke. Для каждого из пяти диалогов выберите preset `policy-knowledge`, завершите тренировку и зафиксируйте `reportStatus`, а также значения browser latency telemetry.

| № | Реплики сотрудника | Что проверить |
| --- | --- | --- |
| 1 | Дать корректный ответ о подозрительном письме и безопасном действии | Сценарий сохраняется, report `READY` |
| 2 | Сначала предложить открыть ссылку, затем исправиться после вопроса тренера | Контекст исправления сохраняется, report отражает его |
| 3 | Отвечать односложно: «Да», «Не знаю», «Проверю» | Нет зависания или потери turn |
| 4 | Во время ответа тренера нажать PTT и дать новую реплику | Старая речь/субтитры не возвращаются, `interruption_to_silent_ms` сохранена |
| 5 | Поправить неверно понятый контекст: «Нет, письмо пришло не от коллеги, а от неизвестного отправителя» | Следующий вопрос учитывает уточнение |

Для каждого прогона подтвердите: сессия `FINISHED`, report `READY`, стенограмма сохранена, report доступен после reload. Цель — минимум 4 успешных из 5; реальные результаты не следует заполнять заранее.

## Метрики

- `voice_end_to_first_audio_ms` — от отпускания PTT до события `simli_speaking`; это ближайший доступный browser proxy первого слышимого аудио, SLO ≤ 3000 мс.
- `interruption_to_silent_ms` — от PTT interrupt до `simli_silent`, SLO ≤ 300 мс.
- Для итоговой сводки используйте фактически сохранённые значения: `count`, `median`, `p95`, `max`, `passRate`. Не подставляйте числа без прогона.

## Lip-sync

SDK не даёт timestamps фонем и видео-кадров, поэтому `simli_speaking` не является метрикой lip-sync. Запишите короткую фразу «Папа попросил проверить письмо» вместе с системным аудио при 60 fps. Сравните onset аудио и движение губ: 200 мс соответствуют 12 кадрам. Результат фиксируется вручную как максимальное наблюдаемое смещение.
